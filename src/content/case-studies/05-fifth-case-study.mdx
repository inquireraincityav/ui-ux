<CsSection label="Context & Problem">
  <CsStatement>
    <span class="accent">Long & McQuade</span> is Canada's largest music and pro-audio retailer - but their gear rental flow still runs on manual quote requests resolved over phone and email.
  </CsStatement>

  Today, renting from L&M means browsing a category page, finding items one at a time, and submitting a quote request that staff resolve manually. There is no real-time availability, no way to build a multi-item kit in one session, and no visibility into which branch actually has stock. For a first-time renter picking up a single mic, that friction is tolerable. For an event professional assembling a full PA rig across multiple days and potentially multiple branches, it is a dealbreaker.

  Peer-to-peer platforms like ShareGrid and KitSplit have solved per-item availability calendars and multi-item insurance stacking - but they are peer-to-peer marketplaces, not a single retailer's own inventory. **The gap nobody has closed is real-time availability, multi-item kit curation, and cross-branch fulfillment from one company's own stores, combined into a single self-serve flow.**
</CsSection>

<CsSection label="Information Architecture">
  <CsStatement>
    The IA splits into two entry paths that converge at a shared cart - then fans out again for post-rental logistics
  </CsStatement>

  The first-time renter enters through **Browse and Search** - a guided category filter with date-range availability, pulling real L&M product data into a card grid. The event professional enters through **GearGenie** - an AI-driven kit builder that takes event type, guest count, venue type, and dates, then returns a recommended gear list.

  Both paths converge at the **Cart**, where the cross-location fulfillment resolver does the work nobody else has built - detecting when items in a single order span multiple branches and offering consolidation. From there, **Checkout** surfaces deposit terms and delivery options inline, and the flow fans out to **Pickup and Return** (mobile-first condition check-in) and **Order History** (repeat-kit reordering for pros).

<CsSection label="GearGenie - The Core Differentiator">
  <CsStatement>
    GearGenie turns "I have a wedding for 150 guests next Saturday" into a priced, in-stock gear list - without a single phone call
  </CsStatement>

  The recommendation engine takes four inputs: event type, guest count, venue (indoor, outdoor, or mixed), and rental dates. It runs deterministic rule matching - not a black-box LLM - against two data layers: four named kit templates that L&M staff already quote manually (Standard PA, Panel/Conference, Recording/Hybrid Meeting, Presentation + Projector), and a heuristic rules table covering scenarios those templates do not (weddings, DJ sets, outdoor festivals).

  When a request matches a named template closely, GearGenie returns it directly - fast and predictable. When it does not, the engine looks up target wattage, speaker counts, mic counts, and mixer channel minimums from the heuristic rules, then matches those specs against real in-stock items from L&M's inventory to assemble a live gear list. Every recommendation links back to actual catalog data. Nothing is invented.

<CsSection label="Cross-Location Fulfillment">
  <CsStatement>
    The cart solves the problem nobody else in the competitive landscape has touched - what happens when your kit spans two branches
  </CsStatement>

  When a user adds items that are stocked at different L&M locations, the cart detects the split and surfaces it immediately: "Your kit will be split across 2 locations - Toronto (Bloor St.) and Toronto (Yorkdale) - you will need two pickups." A Consolidate button lets the user attempt to source everything from one branch, subject to availability.

  This is not an edge case. For an event pro renting a full PA setup, cross-branch fulfillment is the norm. The competitive teardown found that neither ShareGrid nor KitSplit has solved this because they are peer-to-peer - items come from different owners, not different branches of the same retailer. L&M's multi-branch inventory is the asset; the cart is the feature that makes it usable.

<CsSection label="Surfacing Hidden Information">
  <CsStatement>
    Rental terms, deposit requirements, and pricing tiers are surfaced inline - not buried in a FAQ page disconnected from the product
  </CsStatement>

  On L&M's current site, critical rental information - ID requirements, deposit amounts for cash payments, hold fees for advance reservations - lives on a separate FAQ page. A renter discovers these terms after they have already committed to the rental, not before. The redesign moves this information to two places where it belongs: the Gear Detail drawer (inline with the item the user is considering) and the Checkout screen (inline with the payment form).

  Pricing is shown as day, week, and month tiers by default. When the user has already set a date range upstream in Browse or GearGenie, the detail drawer resolves to an actual total for that exact rental window instead of showing only generic rates.

<CsSection label="Design Principles">
  <CsStatement>
    Four principles shaped every screen in the flow - from browse through post-rental
  </CsStatement>

  <CsPrincipleGrid>
    <CsPrinciple title="Pro-First, Newcomer-Safe">
      The event professional's multi-item, multi-day workflow drives the architecture. The first-time renter gets a simpler path into the same system - not a dumbed-down version.
    </CsPrinciple>
    <CsPrinciple title="Real Data, No Fiction">
      Every price, every item, and every kit recommendation traces back to L&M's actual catalog. GearGenie's heuristic rules produce deterministic results - nothing is hallucinated.
    </CsPrinciple>
    <CsPrinciple title="Surface the Hidden">
      Rental terms, deposit rules, and cross-branch splits are shown at the point of decision, not after commitment. If the information affects the user's choice, it belongs on the screen where they are choosing.
    </CsPrinciple>
    <CsPrinciple title="Solve the Unsexy Problem">
      Cross-location fulfillment is not glamorous, but it is the real pain point for anyone renting more than two items. The cart's split-detection and consolidation logic is the feature the competitive landscape is missing.
    </CsPrinciple>
  </CsPrincipleGrid>
</CsSection>
