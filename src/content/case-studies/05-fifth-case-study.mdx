<CsSection label="Context & Problem">
  <CsStatement>
    <span class="accent">Long & McQuade</span> is Canada's largest music and pro-audio retailer - but their gear rental flow still runs on manual quote requests resolved over phone and email.
  </CsStatement>

  Today, renting from L&M means browsing a category page, finding items one at a time, and submitting a quote request that staff resolve manually. There is no real-time availability, no way to build a multi-item kit in one session, and no visibility into which branch actually has stock. For a first-time renter picking up a single mic, that friction is tolerable. For an event professional assembling a full PA rig across multiple days and potentially multiple branches, it is a dealbreaker.

  Peer-to-peer platforms like ShareGrid and KitSplit have solved per-item availability calendars and multi-item insurance stacking - but they are peer-to-peer marketplaces, not a single retailer's own inventory. **The gap nobody has closed is real-time availability, multi-item kit curation, and cross-branch fulfillment from one company's own stores, combined into a single self-serve flow.**
</CsSection>

<CsSection label="Information Architecture">
  <CsStatement>
    The IA splits into two entry paths that converge at a shared cart - then fans out again for post-rental logistics
  </CsStatement>

  The first-time renter enters through **Browse and Search** - a guided category filter with date-range availability, pulling real L&M product data into a card grid. The event professional enters through **GearGenie** - a deterministic kit builder that takes event type, guest count, venue type, and dates, then returns a recommended gear list.

  Both paths converge at the **Cart**, where the cross-location fulfillment resolver does the work nobody else has built - detecting when items in a single order span multiple branches and offering consolidation. From there, **Checkout** surfaces deposit terms and delivery options inline, and the flow fans out to **Pickup and Return** (mobile-first condition check-in) and **Order History** (repeat-kit reordering for pros).

<CsSection label="GearGenie - The Core Differentiator">
  <CsStatement>
    GearGenie turns "I have a wedding for 150 guests next Saturday" into a priced, in-stock gear list - without a single phone call
  </CsStatement>

  The recommendation engine takes four inputs: event type, guest count, venue (indoor, outdoor, or mixed), and rental dates. It runs deterministic rule matching - not a black-box LLM - against two data layers: four named kit templates that L&M staff already quote manually (Standard PA, Panel/Conference, Recording/Hybrid Meeting, Presentation + Projector), and a heuristic rules table covering scenarios those templates do not (weddings, DJ sets, outdoor festivals).

  When a request matches a named template closely, GearGenie returns it directly - fast and predictable. When it does not, the engine looks up target wattage, speaker counts, mic counts, and mixer channel minimums from the heuristic rules, then matches those specs against real in-stock items from L&M's inventory to assemble a live gear list. Every recommendation links back to actual catalog data. Nothing is invented.

<CsSection label="GearGenie Trust States">
  <CsStatement>
    The engine communicates three distinct confidence levels - each with different visual treatment - so the user always knows how much inference went into their result
  </CsStatement>

  Most recommendation systems present every result with equal confidence. GearGenie does the opposite: the UI changes based on how the result was produced. A template match gets a green badge and a named package; a heuristic assembly gets a different label and a tier disclosure; a no-match gets an honest fallback. The user can always tell whether they are looking at a known combination or a computed suggestion.

  <CsCardGrid columns={3}>
    <CsCard title="Template Match" dots={1}>
      <ul>
        <li><strong>Trigger:</strong> Event type maps directly to one of four named L&M packages (Standard PA, Panel/Conference, Recording/Hybrid, Presentation + Projector)</li>
        <li><strong>UI signal:</strong> Green badge - "Matches our [Package Name]"</li>
        <li><strong>Confidence:</strong> Highest - this is a pre-quoted combination that L&M staff already use</li>
        <li><strong>Disclosure:</strong> "This matches our pre-built [name]. Items and quantities are based on real packages quoted by Long & McQuade for similar events."</li>
      </ul>
    </CsCard>
    <CsCard title="Heuristic Match" dots={2}>
      <ul>
        <li><strong>Trigger:</strong> No template fits, but the heuristic rules table has a row for the event type, guest count, and venue</li>
        <li><strong>UI signal:</strong> "Suggested based on your event size" with tier label</li>
        <li><strong>Confidence:</strong> Medium - the engine assembled a custom list from target specs (watts/guest, speaker counts, mixer channels)</li>
        <li><strong>Disclosure:</strong> Shows the underlying rule - e.g. "6-8W/guest, indoor, 300-400 guests. 2 speakers, 2 wireless + 3 wired mics, 8+ mixer channels."</li>
      </ul>
    </CsCard>
    <CsCard title="No Match" dots={3}>
      <ul>
        <li><strong>Trigger:</strong> Parameters fall outside all sizing tiers (extreme guest count, Custom event type with no reasonable fallback)</li>
        <li><strong>UI signal:</strong> Info icon - "No close match found"</li>
        <li><strong>Confidence:</strong> N/A - graceful degradation rather than a forced bad recommendation</li>
        <li><strong>Fallback:</strong> Suggests contacting a Long & McQuade location directly, echoing the real L&M flow this screen is otherwise improving on</li>
      </ul>
    </CsCard>
  </CsCardGrid>

  The resolution logic runs in strict priority order: template match first, heuristic fallback second, no-match last. When a guest count falls between two heuristic tiers, the engine defaults to the nearer or larger tier and surfaces which tier it matched. When an item in the suggested list has no confirmed price, it displays "Price to be confirmed" on that line item rather than showing $0 or silently excluding it from the total. The design principle is the same throughout: **if the system is uncertain, say so - do not paper over the gap.**
</CsSection>

<CsSection label="Cross-Location Fulfillment">
  <CsStatement>
    The cart solves the problem nobody else in the competitive landscape has touched - what happens when your kit spans two branches
  </CsStatement>

  When a user adds items that are stocked at different L&M locations, the cart detects the split and surfaces it immediately: "Your kit will be split across 2 locations - Toronto (Bloor St.) and Toronto (Yorkdale) - you will need two pickups." A Consolidate button lets the user attempt to source everything from one branch, subject to availability.

  This is not an edge case. For an event pro renting a full PA setup, cross-branch fulfillment is the norm. The competitive teardown found that neither ShareGrid nor KitSplit has solved this because they are peer-to-peer - items come from different owners, not different branches of the same retailer. L&M's multi-branch inventory is the asset; the cart is the feature that makes it usable.

<CsSection label="Surfacing Hidden Information">
  <CsStatement>
    Rental terms, deposit requirements, and pricing tiers are surfaced inline - not buried in a FAQ page disconnected from the product
  </CsStatement>

  On L&M's current site, critical rental information - ID requirements, deposit amounts for cash payments, hold fees for advance reservations - lives on a separate FAQ page. A renter discovers these terms after they have already committed to the rental, not before. The redesign moves this information to two places where it belongs: the Gear Detail drawer (inline with the item the user is considering) and the Checkout screen (inline with the payment form).

  Pricing is shown as day, week, and month tiers by default. When the user has already set a date range upstream in Browse or GearGenie, the detail drawer resolves to an actual total for that exact rental window instead of showing only generic rates.

<CsSection label="Accessibility">
  <CsStatement>
    Every screen in the flow was built against four accessibility requirements - contrast, touch targets, focus states, and error handling
  </CsStatement>

  <CsCardGrid columns={2}>
    <CsCard title="Contrast & Color" dots={1}>
      <ul>
        <li><strong>WCAG AA compliance:</strong> All body text meets a minimum 4.5:1 contrast ratio against surface colors; large headings meet 3:1</li>
        <li><strong>Dual-channel status:</strong> Availability indicators (In Stock / Out) and success/warning states use both color and iconography - never color alone</li>
        <li><strong>Surface hierarchy:</strong> Raised cards, input fields, and interactive surfaces maintain contrast against the base background through border and shadow, not just fill color</li>
      </ul>
    </CsCard>
    <CsCard title="Touch & Interaction" dots={2}>
      <ul>
        <li><strong>44px minimum targets:</strong> All buttons, steppers, toggle controls, and tappable rows maintain a 44x44px minimum touch target - including the quantity steppers in the cart and kit builder</li>
        <li><strong>Visible focus states:</strong> Every interactive element carries a visible focus ring for keyboard and assistive-device navigation</li>
        <li><strong>Inline error handling:</strong> Form validation errors surface immediately below the relevant field with a descriptive message - not in a disconnected toast or modal that requires context-switching</li>
      </ul>
    </CsCard>
  </CsCardGrid>

<CsSection label="Design Principles">
  <CsStatement>
    Four principles shaped every screen in the flow - from browse through post-rental
  </CsStatement>

  <CsPrincipleGrid>
    <CsPrinciple title="Pro-First, Newcomer-Safe">
      The event professional's multi-item, multi-day workflow drives the architecture. The first-time renter gets a simpler path into the same system - not a dumbed-down version.
    </CsPrinciple>
    <CsPrinciple title="Real Data, No Fiction">
      Every price, every item, and every kit recommendation traces back to L&M's actual catalog. GearGenie's heuristic rules produce deterministic results - nothing is hallucinated.
    </CsPrinciple>
    <CsPrinciple title="Surface the Hidden">
      Rental terms, deposit rules, and cross-branch splits are shown at the point of decision, not after commitment. If the information affects the user's choice, it belongs on the screen where they are choosing.
    </CsPrinciple>
    <CsPrinciple title="Solve the Unsexy Problem">
      Cross-location fulfillment is not glamorous, but it is the real pain point for anyone renting more than two items. The cart's split-detection and consolidation logic is the feature the competitive landscape is missing.
    </CsPrinciple>
  </CsPrincipleGrid>

<CsSection label="Reflection & Future Work">
  <CsStatement>
    The core bet held up - a single retailer's multi-branch inventory is an asset, not a constraint, if the fulfillment logic is surfaced properly
  </CsStatement>

  GearGenie's three trust states let the system be honest about how much inference went into a recommendation rather than presenting everything with equal confidence. The cross-location fulfillment resolver solves a real logistics gap that peer-to-peer competitors structurally cannot address - their items come from different owners, not different branches of the same retailer.

  The decision to use deterministic rule matching over an LLM for the recommendation logic was validated in testing: users trusted the output more when they could see the underlying rule ("6-8W/guest, indoor, 300-400 guests") than when they received an opaque "AI-generated" suggestion. The "Why this list" disclosure, initially designed as a pro-user feature, turned out to matter for first-time renters as well - it answered the question "can I trust this?" before it was asked.

  **What is next:** the mobile-first Pickup and Return condition check-in flow (photo capture for pre/post-rental damage documentation), visual polish applying iOS's Liquid Glass design language, expanded heuristic rules for outdoor events and festivals, and real-time inventory sync for live stock status.
